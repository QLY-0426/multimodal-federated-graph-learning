# V4 合成特征探针（2026-11-03）

目的：判断凝缩图失效的根因在“合成特征内容”还是在“图/边结构”。

协议：全部只读 V1 缓存与原始数据，不改生产源码。把同一套 32 维 MLP（与 V3 mlp_only 锚点完全一致：lr=.01、weight_decay=0、500 轮、种子 500/501/502）分别喂给三种特征，在同一个真实客户端 val 上打分：- `syn_feat`：缓存合成图的特征，完全不用任何边（等价 pure-feature MLP）；
- `real_subset`：真实训练节点中按合成图完全相同的每类配额抽出的子集（样本量对齐）；
- `real_full`：全部真实训练节点（样本量上限参照）。

这三者之间唯一的差别是“特征从哪来/有多少”，不含任何图结构，因此可以直接回答“合成特征本身还能不能用”。同时给出 `gcn_on_syn` 一列，即 V3 阶段 B 里同一个合成图配 GCN 学生的分数，用于对照“加边到底帮了还是害了”。

## 判定

- **Movies**：syn_feat 28.17｜real_subset 40.08｜real_full 40.76｜gcn_on_syn 31.60。合成特征比同数量真实特征低 11.91 pp，特征内容已明显退化；加上边带来 +3.43 pp，边结构有正贡献。
- **Toys**：syn_feat 34.90｜real_subset 62.81｜real_full 69.41｜gcn_on_syn 23.82。合成特征比同数量真实特征低 27.91 pp，特征内容已明显退化；但给这张图加上边之后反而再降 11.07 pp，边结构是负资产。

## 边界

本探针是诊断而非因果证明：它只能说明“当前缓存里的合成特征还能不能被线性/浅层模型使用”，不能直接证明是 feat_alpha、PGE 还是采样配额造成的。若 syn_feat 与 real_subset 差距明显，下一步才值得重跑凝缩并消融 feat_alpha；若两者接近，则应回头查边与传播而非特征。
所有数字均在同一真实客户端 val 上取得，该 val 也参与了 V1 的选图，存在选择偏差。
